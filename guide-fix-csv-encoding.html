Fixing garbled characters in a CSV file

You open a CSV and “José” shows up as “JosÃ©”, “Zürich” as “ZÃ¼rich”, or curly quotes as “â€™”. Nothing is wrong with the data itself; it is being read with the wrong text encoding.

What an encoding is

A file stores text as bytes, and an encoding is the rule that turns those bytes back into letters. Plain English letters look the same in almost every encoding, which is why the problem only appears with accents, symbols and non-Latin scripts. The two encodings you meet most often in CSV files are:

  • UTF-8, the modern standard, which can represent every language. Most databases, web apps and APIs export UTF-8.
  • Windows-1252 (often called Latin-1 or ANSI), an older Western European encoding still used by some Windows programs.

In UTF-8, “é” is stored as two bytes. Read those two bytes as Windows-1252 and you get two characters, “Ã©”. That pattern of an “Ã” or “â€” followed by another symbol is the signature of UTF-8 text read as Windows-1252.

The other symptom: question marks and �

The opposite mistake looks different. If a Windows-1252 file is read as UTF-8, some bytes are simply invalid, and they show up as the replacement character “�” or as question marks. The Inspect tool reports both symptoms: it counts rows with undecodable characters and warns about likely garbled text.

How to fix it

  1. Open the file in any tool and expand Encoding and delimiter in the file panel. The detected encoding is shown there.
  2. If the preview shows “Ã©”-style text, choose UTF-8. If it shows � or question marks, choose Windows-1252. The preview and row counts update straight away.
  3. Once the text looks right, use the Convert tool to save a clean copy. For general use pick UTF-8. If the file is going to be opened in Excel by double-clicking, pick UTF-8 with BOM.

Why Excel needs the BOM

When Excel opens a CSV by double-click, it guesses the encoding, and without a hint it usually guesses the local Windows encoding. A byte-order mark (BOM) is a short invisible marker at the start of the file that tells Excel the file is UTF-8. Adding it is the simplest way to make accents survive a double-click.

When the damage is permanent

If a file has already been opened with the wrong encoding and then saved, the garbled text is now the actual content, sometimes several layers deep. Re-reading it with a different encoding may not help. In that case the most reliable fix is to go back to the original export. To avoid the problem next time, export as UTF-8 and keep the original file untouched.
